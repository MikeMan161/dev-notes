----------------------------------------------------------------
  DAILY NON-NEGOTIABLES (every single day, no exceptions)
----------------------------------------------------------------
  [ ] 1 LeetCode problem (NeetCode 150 order) — 20-30 min MAX
      - Struggle 20 min before looking at any solution
      - After watching solution, close it and solve again yourself
      - Revisit problems every 3 days (spaced repetition)

  [ ] 1 Git commit — always be building something
      - Even a small refactor or README update counts
      - Green contribution graph = recruiters notice

  [ ] Read 1 thing — tech news, AI developments, industry trends
      - 10-15 min, keeps you sharp and interview-conversational

  [ ] Brief reflection — what did I actually learn today?
      - One sentence is fine. Builds metacognition over time.

----------------------------------------------------------------
  LEETCODE ORDER (NeetCode 150 — neetcode.io)
----------------------------------------------------------------
  Start here, in this order:
  1. Arrays & Hashing       (foundation — do this first)
  2. Two Pointers           (covers ~40% of real interviews)
  3. Sliding Window         (with above, you're already ahead)
  4. Stack
  5. Binary Search
  6. Linked List
  7. Trees
  8. Tries
  9. Heap / Priority Queue
  10. Backtracking
  11. Graphs
  12. Dynamic Programming   (don't rush here, build up to it)

  Platform: neetcode.io for roadmap + videos (free)
            leetcode.com for actually solving problems (free tier)

----------------------------------------------------------------
  PHASE 1 — FOUNDATION
  April → May 2026 (8 weeks)
----------------------------------------------------------------
  PRIMARY GOAL: Ship a working finance tracker MVP locally.
                Learn the stack by building, not by reading docs.

  PROJECT: AI-Powered Personal Finance Tracker
  Stack:   React + TypeScript (frontend)
           FastAPI / Python   (backend)
           PostgreSQL         (database)
           Claude / OpenAI    (AI layer — add in Phase 2)
           AWS                (deployment — add in Phase 2)

  Week 1-2: Architecture & Setup
  - Write a plain English description of what the app does
  - Design your data model (users, transactions, categories)
  - Map your API endpoints before writing any of them
  - Set up the repo with a good README from day one
  - Initialize React+TS frontend and FastAPI backend

  Week 3-4: Core Backend
  - Build user auth (JWT)
  - CRUD routes for transactions
  - PostgreSQL schema, SQLAlchemy models
  - Test every route manually before moving on

  Week 5-6: Core Frontend
  - Connect React frontend to FastAPI backend
  - Transaction input form, list view, basic dashboard
  - TypeScript types for all your data models

  Week 7-8: Polish MVP
  - Basic spending categorization (manual first)
  - Simple chart or summary view
  - Clean up code, write comments you'd be proud of
  - Solid README with screenshots

  GIT HABITS TO BUILD NOW:
  - Descriptive commit messages ("add JWT auth route" not "fix stuff")
  - Feature branches (not everything on main)
  - Use GitHub Issues to track your own tasks
  - Pin this repo on your GitHub profile

----------------------------------------------------------------
  PHASE 2 — AI LAYER + CLOUD DEPLOYMENT
  May → July 2026 (8 weeks)
----------------------------------------------------------------
  PRIMARY GOAL: Make the finance tracker live and impressive.
                Add the AI features that make it stand out.

  Week 1-2: AI Integration
  - Add Claude or OpenAI API to backend
  - Auto-categorize transactions using LLM
  - Natural language query endpoint
    ("how much did I spend on food last month?")

  Week 3-4: Pattern Detection
  - Spending pattern insights ("you spend 40% more on weekends")
  - Anomaly flagging ("this month's dining is unusually high")
  - Optional: FRED API for economic benchmarks

  Week 5-6: AWS Deployment
  - Deploy FastAPI backend on AWS Elastic Beanstalk (free tier)
  - PostgreSQL on AWS RDS (free tier)
  - React frontend on S3 + CloudFront or Vercel
  - Get a live, shareable URL you can put on your resume

  Week 7-8: Portfolio Documentation
  - Write a proper README: what it does, why you built it,
    tech decisions, screenshots, live demo link
  - Write a short case study for your portfolio site
  - Record a 2-minute demo video (huge for standing out)
  - Update resume with this project (only after it's real)

  RESUME RULE: Never list a project until it's actually built
               and deployed. Then list it with the live URL.

----------------------------------------------------------------
  PHASE 3 — SECOND PROJECT + JOB SEARCH BEGINS
  July → September 2026 (8 weeks)
----------------------------------------------------------------
  PRIMARY GOAL: Build something you genuinely care about.
                Start putting yourself out there.

  PROJECT 2: Something in sports, community, or social impact
  - Pick a domain you actually care about
  - Use at least one public API (sports data, events, etc.)
  - AI-integrated, full-stack, deployed
  - Should solve a problem you've personally experienced

  Week 1-4: Build Project 2
  - Same architecture discipline as Project 1
  - Apply everything you learned — faster this time
  - Document as you go, not after

  Week 5-6: Resume + LinkedIn Overhaul
  - Both real projects on resume with live URLs
  - ATS-optimized with keywords from job descriptions
  - LinkedIn: update projects, skills, add demo video links
  - Ask a friend or professor to review it

  Week 7-8: Start Applying
  - Target: startups, mid-size tech companies, AI-adjacent roles
  - Use: Hiring Cafe, Simplify, LinkedIn, Handshake, Indeed
  - Customize resume per application (5-10 min targeted edits)
  - Apply to ~10-15 roles per week minimum
  - Don't wait until you feel "ready" — apply now

  ON SHARING YOUR WORK (getting over the fear):
  - Post a LinkedIn update about what you built and why
  - Share a screenshot or short video of it working
  - You're not publishing for critics — you're building a trail
  - Nobody will scrutinize your finance app harshly
  - A recruiter will see: shipped product + green GitHub + story
  - That's the whole game. The bar is lower than you think.

----------------------------------------------------------------
  PHASE 4 — DEPTH + INTERVIEWS
  September → November 2026 (8 weeks)
----------------------------------------------------------------
  PRIMARY GOAL: Convert applications into offers.
                Go deeper technically, get interview-ready.

  Week 1-3: Ramp Up LeetCode
  - Move into medium+ difficulty problems
  - Start reviewing Trees and Graph problems
  - Time yourself — practice under pressure

  Week 4-5: System Design Basics
  - You won't get deep system design at internship level
  - But know the basics: load balancers, databases, caching,
    APIs, horizontal vs vertical scaling
  - Resources: "System Design Primer" (free, GitHub)

  Week 6-7: Mock Interviews
  - Practice talking through problems out loud
  - Use Pramp (free mock interviews with real people)
  - Record yourself explaining your projects — watch it back
  - The goal: explain any part of your project to anyone

  Week 8: Project 3 (optional)
  - Open source contribution (adds collaborative cred)
  - OR portfolio site redesign (make it clean and minimal)
  - Only if bandwidth allows — interviews take priority now

  TALKING ABOUT YOUR WORK:
  - Post on LinkedIn about your build process
    ("here's a problem I ran into and how I solved it")
  - This builds a public record of your thinking
  - Engineers who can communicate are rare and valuable
